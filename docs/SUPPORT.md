# Supported release scope

| Route | Implementation | Evidence boundary |
|---|---|---|
| DOP-B | DOPSoft 2 file backend; nine plan/edit/save tools and five durable job tools | Exact profile/source contracts; qualified existing controls and donor-bound creation only |
| DOP-100 | Independent DIAScreen file backend;30 audited tools and isolated project sessions | Hash-pinned native layout, bounded operations and saved-layer previews |

Full support descriptions remain in [DOP-B support](../components/dop_b/docs/SUPPORT_MATRIX.md) and [DIAScreen support](../components/dop_100/docs/SUPPORT_MATRIX.md). The umbrella never translates one native format into the other or guesses a profile from an extension.

## Explicitly incomplete native/runtime features

The historical inventory is complete as a discovery record, not as a promise that every old idea was implemented. General picture-bank import/copy/prune, additional arbitrary macro opcodes, recipes, native alarm history/ACK, trends, account/security constructors, multilingual resources, system widgets, popup constructors, S7 mapping and custom asset builders are unsupported constructors or explicitly unqualified/contract-only areas in this release; the matrix states which cases have no implementation. Existing opaque content is preserved or the affected operation is refused.

Operating-mode atomicity, TIME conversion, ramp freshness, fault/home/drive interface behavior and PLC working feedback are contract-bound. Rolled-back heartbeat scheduling is not reinstated. This package cannot make missing PLC logic or physical hardware appear by installing software.

No vendor, native pixel, panel or physical acceptance is inferred from synthetic tests, support-table rows or agent agreement. Real model acceptance is recorded with the exact file hash and scenario.
