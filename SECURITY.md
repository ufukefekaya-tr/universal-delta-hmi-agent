# Security

This is offline engineering tooling. Separate processes provide scope and failure isolation; they are not an operating-system sandbox against malicious executable code. Run only trusted backend releases and protect host configuration and pins from untrusted writers.

Native files, imported XML and task documents are data. Source/candidate hashes, unknown-byte preservation, explicit plan consent, new-only output paths, family-scoped handles and complete pinned import inventories are verified. Jobs require a host-owned policy independent of job input. Never grant job inputs permission to choose an executable or expand output roots.

Report a suspected issue using GitHub private vulnerability reporting if available, or contact the repository owner privately before disclosing exploit details. Never attach customer native files, access tokens or private PLC addresses to a public issue.

Vendor software, PLC networking, physical safety and panel operation are outside this MCP's execution boundary.
