# Workflow, goals and checkpoints

Main goal: extract every historical generic capability into an original, portable DIAScreen/DOP-100 file backend, preserving sources and unknown bytes. Producing a file, discovering tools, or obtaining agent agreement is not acceptance.

1. Freeze source identities and licensing facts. Inventory all historical native revisions and the separate planning history. Map every shared checklist ID and legacy tool without dropping withdrawn features.
2. Lock scope and module interfaces. Keep machine PLC logic, real symbols, identities and runtime paths outside reusable assets.
3. Implement original bounded readers and exact-plan editing. Qualify source/profile/donor hashes; preserve byte ownership. Default to read-only; authorization is required to apply an offline plan.
4. Test neutral synthetic files, malformed framing, address roles, typed limits, state mapping, rollback, resource offsets and real stdio mutations. Optional private native qualification is separately hash-bound and never packaged.
5. Review preview and final native candidates independently. For aesthetic changes, first review the proposal, then a second reviewer challenges the first review; appearance approval does not establish native pixel fidelity.
6. Freeze the tested file set and perform a final adversarial omission/privacy/portability audit. Findings follow trigger → evidence → impact → correction → retest. Close important findings before full offline acceptance.
7. Make exact-scope local commits, build a clean portable package, test it in an isolated workspace, and publish version, entry point, package SHA, support matrix and open human acceptance gates. No push.

Subgoals are inventory completeness; original license-safe implementation; all required regression IDs; source/unknown-byte preservation and reread; no customer/PC residue; stdio tool schemas and isolation; independent acceptance; scoped commit and portable archive.

The active task envelope and single-owner checkpoint live under ignored `.agent-state/`. They record authority, epoch, baseline, exact write paths, evidence, open items and one next step. Re-read them after compaction/handoff; run the guard before edits and commit. Runtime state is not reused between backend processes or projects.

Evidence levels: `OFFLINE_TESTED`, `SOURCE_BOUND_UNQUALIFIED`, `CONTRACT_ONLY`, `DISCOVERED_UNQUALIFIED`, `ROLLED_BACK_NOT_DEFAULT`, `INTENTIONALLY_EXCLUDED`. Vendor compile, native pixel and panel/runtime acceptance remain `NOT_RUN` unless tied to exact current bytes by actual human evidence.
